Imagine an agent in a long chat. When it needs a fact from a library of documents, the usual habit is: write a short search sentence, hand that sentence to a second specialist model, get a list of numbers (an embedding), then find nearby documents. That two-step habit grew out of RAG and search engines. It works, but it treats the chat model as a typist and the embedder as the only one who “understands” the question.

The paper’s complaint is waste. While the agent writes that search sentence, it already built a rich internal picture of the whole conversation — pronouns, earlier turns, what the user actually wants. Those pictures live in **hidden states**, the numbers inside the model at each word. Then the pipeline throws them away, prints a short sentence, and asks another model to rebuild meaning from scratch. That second pass costs time, extra hardware, and often loses context the first model already had.

Older patches did not remove the second model. People rewrote queries so they stood alone. HyDE had the model invent a fake answer document and embed *that*. Other work turned whole LLMs into embedders (LLM2Vec, NV-Embed), but you still run a separate “embedding mode” pass. This paper wants something smaller: keep the agent doing its normal talking, **keep the hidden states it already computed**, and learn a tiny translator that turns those states into the same number-space the document index already uses.

How the translator works, in kitchen terms: as the agent generates the search sentence, save the hidden state at each word. A small network (about 25 million parameters vs an 8-billion-parameter brain) looks across those states, averages them, and outputs one vector the same size as the teacher embedder’s vectors. Normalize it so “nearby” still means cosine similarity. At search time you never call the embedder.

They teach that translator by copying a teacher. Here both models are in the Qwen3 family: Qwen3-8B talks; Qwen3-Embedding-8B is the teacher. Three lessons at once. **Alignment:** make your vector point the same way as the teacher’s for this query. **Contrastive:** your vector for query A should match teacher-A more than teacher-B. **Rank distillation:** if the teacher likes document 3 more than document 7, you should too. Alignment alone is the backbone. Ranking-only fails because the student has no idea *where* in space to stand. All three together work best.

They test on QReCC — multi-turn chats where “that one” only makes sense if you remember earlier turns. Baseline: generate a rewritten query, embed it, retrieve. Their method: same chats, hidden states → small head → retrieve. Quality drops a little: Recall@10 0.637 → 0.607 (about 95–97% of the old score). Per-query encoding time 43.5 ms → 2.0 ms, because you skip the second big model. On most questions the two systems pick the same winners; the misses cluster on odd conversations (rare words, messy references).

Training is fussy. Too high a learning rate and the mapping collapses. Longer, slower training helps more than any single loss trick. The embedder is still needed *while you train* the head; you only drop it when serving. They only tried one dataset and same-family models. Crossing into a totally different embedder family is unproven. So this is not “embeddings are dead.” It is: for an agent that already thought about the conversation, you often do not need a second brain just to point at memory — a small learned pointer on the first brain is almost as good, and much cheaper at lookup time.
